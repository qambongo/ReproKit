ReproKit

Share report links

Configure a Supabase project to upload a self-contained report and create an expiring link developers can open in a browser.

One-time Supabase setup

Create the private bucket and limited upload/read policies in your Supabase project’s SQL Editor. The publishable/anon key is intended for client use; never use a secret or service_role key here.

insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('reprokit-reports', 'reprokit-reports', false, 52428800, array['text/html'])
on conflict (id) do update set
  public = false,
  file_size_limit = 52428800,
  allowed_mime_types = array['text/html'];

drop policy if exists "ReproKit report uploads" on storage.objects;
create policy "ReproKit report uploads"
on storage.objects for insert to anon
with check (bucket_id = 'reprokit-reports');

drop policy if exists "ReproKit signed report links" on storage.objects;
create policy "ReproKit signed report links"
on storage.objects for select to anon
using (bucket_id = 'reprokit-reports');

These anon policies are intentionally simple, not access-controlled: anyone who can call your project can upload, list report paths, and create signed links for reports in this bucket. Do not treat uploaded reports as private or store sensitive recordings. Use a dedicated project/bucket and monitor storage usage. Link expiry does not delete the uploaded report.
